# 项目 Harness 与文件职责整理 Spec

## 1. 工作包

- 工作包：`M0-04 Harness 与文档闭环`
- 项目类型：私有化知识平台，全栈 pnpm Monorepo
- 团队规模：2–5 人

## 2. 目标

让 Agent 从根 Harness 即可确定项目入口、文件职责、架构边界、验证命令和文档闭环，减少重复扫描与规则漂移。

## 3. 范围

- 整理根 `AGENTS.md`，保留通用规则的单一真相源。
- 保持 `CLAUDE.md` 为 `@AGENTS.md` 桥接，只承载 Claude 专属规则。
- 对齐实际技术栈、目录、命令、组件化阈值和 D-S-T-E 体验规则。
- 更新 `spec/INDEX.md`、交付状态、`doc/INDEX.md` 与当日日志。

## 4. 非范围

- 不移动 `apps/`、`packages/`、`runtimes/`、`skills/` 或 `doc/` 现有文件。
- 不删除 `output/`、`test-results/` 或本地数据。
- 不新增 `.claude/rules/`、settings hooks 或嵌套 Harness；当前团队规模和子目录规则分化不足以支持这些维护成本。
- 不修改产品代码、数据库、运行时行为或部署配置。

## 5. 影响面

- Agent 开工读取顺序和文档写回协议。
- TypeScript、React、API、Worker 与 Python JSON CLI 的职责边界。
- 新建和实质修改组件时的拆分判断，以及既有超限文件的处理方式。
- 项目验证、提交和安全约束。

## 6. 验收标准

- `AGENTS.md` 通过技能定义的 13 项质量核验，且少于 200 行。
- Harness 中的命令均能在根 `package.json` 找到或属于 pnpm 内置命令。
- 技术栈、代码风格、目录和依赖方向与当前仓库一致。
- 现有超过 300 行的组件不会被误写成“当前已合规”；规则明确适用于新建或实质修改。
- D-S-T-E 覆盖诊断、简化、翻译和升温四步，并使用项目用户语言。
- `CLAUDE.md` 不复制通用规则，仍以 `AGENTS.md` 为单一真相源。
- 文档索引、状态台账和当日日志同步更新。
- 无业务文件搬迁、生成物删除或产品代码变更。
