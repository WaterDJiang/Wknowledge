# 资源处理实时进度 M2-07/M2-10 实施 Spec v1

## 1. 关联计划

- 工作包：`M2-07 进度协议`、`M2-10 处理 UI`。
- 当前基础：上传接口返回 `jobId`，Worker 持久化 `status/stage/progress/error`，SSE Route 已能输出任务快照。
- 当前缺口：资料页只在上传响应后刷新一次，用户看不到 queued → parsing → wiki_compile → completed/failed 的变化。

## 2. 目标流程

```text
上传文件
→ 返回 jobId 并刷新资源列表
→ 订阅 /api/jobs/{jobId}/events
→ 更新阶段、百分比和资源状态
→ completed/failed 后关闭订阅
→ 自动刷新最终资源状态
→ 用户进入知识库时读取最新 Wiki 索引
```

## 3. 范围

### 包含

- 资源列表 API 返回每个资源最近一次处理任务的公开状态。
- 页面加载或上传后自动订阅 queued/processing 任务，支持浏览器原生 EventSource 断线重连。
- 资料卡显示中文阶段、百分比和进度条。
- 完成后自动刷新资源列表并提示知识库已更新。
- 失败后显示错误码、错误摘要和当前失败阶段，不泄露堆栈或服务器路径。
- 上传期间禁用重复提交，网络异常后恢复按钮。

### 不包含

- 任务取消、resume、dead-letter 和服务端重试 API；归属 `M2-06`。
- 历史资源版本 UI；归属 `M2-03/M2-10` 后续切片。
- 分片上传和浏览器上传百分比；归属 `M2-01`。
- Wiki 页面粒度改造；已登记到 `M3-01/M3-03/M3-10`。

## 4. 状态契约

- 任务状态：`queued | processing | completed | failed`。
- 当前阶段：`queued | parsing | wiki_compile | retry_wait | completed | failed`；UI 对未知阶段使用“处理中”。
- `retry_wait` 仍属于 `queued`，表示 pg-boss 尚有自动重试次数；只有最终 `failed` 才显示人工重试。
- 进度必须是 0–100 的整数。
- SSE 只传输当前任务快照；客户端不依赖事件历史重建最终状态。
- 页面重载后通过资源列表中的最近任务恢复订阅，不依赖内存中的上传响应。

## 5. 验收标准

- 新文件上传后无需手动刷新即可看到阶段和进度变化。
- 任务完成后资源状态自动变为 ready，页面提示可进入知识库查看。
- 任务失败后资源状态自动变为 failed，并显示阶段、错误码和摘要。
- 页面重载后仍能继续跟踪未完成任务。
- 切换知识空间会关闭旧空间的 EventSource，旧任务不得更新新空间状态。
- 上传请求异常时按钮恢复可用并显示具体失败消息。
- 格式、Lint、类型、单测、构建和浏览器交互验证通过。
