# PDF 原生文字 bbox 精确定位 M4-01 Spec v1

## 1. 关联计划

- 工作包：`M4-01`，依赖 M2-08 `CompiledNode` 与 M4-08/M4-09 受权 PDF 原件预览。
- 状态：已验证。原生文字 bbox 解析保持本 Spec 的范围；浏览器叠层与派生页图由相邻 [PDF 区域预览 Spec](pdf-bbox-preview-m4-01-m4-08-m4-09-v1.md) 接续。

## 2. 目标

- 每个可提取的 PDF 文字块写入不可变 `ResourceVersion`、页码和 PDF point 坐标 bbox。
- 现有 Wiki、查询与学习仍使用相同 `wk://source` 机制，原件继续跳至正确 PDF 页。
- 坐标节点不可将扫描图片、表格或版式理解伪装成文字证据。

## 3. 解析与安全规则

- 使用本地 PyMuPDF 只读打开 PDF，按 `page.get_text("blocks", sort=True)` 的稳定顺序提取原生文本块。
- bbox 记录为 PDF point `[left, top, right, bottom]`；空文本、NaN/Infinity、越出页面媒介框或退化 bbox 不生成节点。
- 单文字块最多 32 KiB UTF-8，每页最多 500 块、整份文件最多 10,000 块；超限安全失败，不输出部分且无法回查的证据。
- 页面没有可提取原生文字时不执行 OCR，且不产生“图片已识别”的内容。扫描件 OCR 作为独立后续切片。

## 4. 来源呈现

- 原有 PDF 预览继续使用受权历史 Blob 和 `#page=n` 打开正确页。
- 带 bbox 的引用可由相邻 M4-08/M4-09 预览切片显示同版本派生页图与精确覆盖层；本 Spec 不把该 UI 视作解析正确率证明。

## 5. 验收标准

- 双页合成 PDF 的文字块产生合法、稳定、同版本一致的 `pdf + page + bbox` 定位。
- 空白页不生成虚构节点；块边界、顺序、页码和 bbox 均通过契约校验。
- Parser 和根质量门禁已通过；真实 PDF 的区域人工抽样与可视化准确率评测仍不得标记为已完成。

## 6. 明确后置

- 扫描件 OCR、表格重建、跨栏/复杂阅读顺序模型、多个区域高亮、M4-10 95% 人工定位评测。
