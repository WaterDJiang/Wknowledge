# Wknowledge 项目章程与总需求基线 v1

## 1. 文档目的

本文件定义 Wknowledge 的产品边界、业务目标、用户旅程、功能域、非功能要求和项目级验收标准，是所有设计与实施计划的上游真相源。

变更本文件中的范围、成功指标或核心约束，必须同步更新：

- `doc/design/system-architecture-v1.md`
- `doc/plan/master-implementation-plan-v1.md`
- 受影响的分域 Spec、设计文档和验收矩阵

## 2. 产品定义

Wknowledge 是一个单仓库、可私有化部署的多模态知识管理与学习应用平台。系统将用户上传的资料转换为可审阅、可查询、可追溯的 Markdown LLM Wiki，并在此基础上提供自由问答、学习计划、课程学习、练习和测评。

产品核心不是“文件聊天”，而是以下闭环：

```text
受控保存原始证据
→ 结构化解析与来源定位
→ 编译为可审阅的 Wiki
→ 基于证据查询和应用
→ 产生学习行为与评测记录
→ 反向更新计划和知识质量
```

## 3. 项目目标

### 3.1 业务目标

- 让个人、团队和部门在自己的基础设施中沉淀多模态资料。
- 将零散文件转化为有目录、有页面、有来源的可维护知识库。
- 让回答、课程和题目能够回到具体原文位置，而不是只给模型结论。
- 将知识管理能力延伸为可执行的学习计划、练习和测评。
- 通过 Skill 扩展解析、分析、编排和评估能力，不把业务固化在单一模型中。

### 3.2 技术目标

- 单仓库管理 Web、API、Worker、数据库、Skill、模型路由和 Python 工具运行时。
- 私有化部署的最小必需组件只有 Web、Worker、PostgreSQL 和受管文件存储。
- Markdown 是知识正文事实源，PostgreSQL 是身份、权限、状态和业务记录事实源。
- 首期查询不依赖向量数据库和 Embedding。
- 原始资料不可变，所有派生内容和输出可追溯到资源版本。

## 4. 目标用户与角色

| 用户类型   | 核心任务                             | 对应角色 |
| ---------- | ------------------------------------ | -------- |
| 系统负责人 | 安装、初始化、配置模型、备份恢复     | owner    |
| 知识管理员 | 管理用户、空间、任务、审计和知识质量 | admin    |
| 知识编辑者 | 上传资料、纠错、审核 Wiki、编排课程  | editor   |
| 学习者     | 阅读、提问、执行计划、练习和测评     | learner  |
| 只读访问者 | 浏览授权 Wiki 和来源                 | viewer   |

权限必须同时满足组织成员身份、知识空间成员身份和操作所需最低角色。

## 5. 关键用户旅程

### J1：资料入库

1. 用户进入有编辑权限的知识空间。
2. 选择文件，系统检查类型、大小、文件签名和配额。
3. 系统创建逻辑资源、不可变版本和后台任务。
4. Worker 解析内容并保存标准节点和定位信息。
5. Wiki 编译任务在空间锁下生成 staging 版本。
6. Schema、链接、来源和冲突检查通过后原子发布。
7. 用户在 UI 中看到处理结果、Wiki 页面和可点击来源。

失败时必须显示失败阶段、可理解摘要、原始错误标识和重试入口。

### J2：知识浏览与纠错

1. 用户从空间 Wiki 目录进入分域索引或页面。
2. 页面显示 Frontmatter 摘要、正文、相关页面和来源清单。
3. 点击引用打开来源预览，并定位到页码、时间点、单元格或结构节点。
4. 编辑者提交纠错建议；人工确认页面不能被自动覆盖。
5. 发布后保留版本、变更日志和审核人。

### J3：自由问答

1. 用户创建或继续一个可恢复的对话会话，并选择本轮可用模型与 Skill。
2. 用户把一个或多个已授权知识库挂载为只读上下文；系统分配受管虚拟路径，不暴露宿主机绝对路径。
3. Agent 按需加载 Skill，通过知识目录、索引搜索、页面读取和来源打开工具获取上下文。
4. 查询仍先读根索引，再读取分域索引和候选页面；必要时回查 compiled 节点，不直接遍历原始文件。
5. 对话模型只基于检索到的证据生成自然语言回答，不把模型常识伪装成知识库内容。
6. 对话支持流式输出、工具状态、停止、继续和多轮上下文裁剪；每次工具调用重新校验权限。
7. 回答正文与源资料分区显示，每个引用关联可解析来源；历史回答固定当时的知识版本。
8. 未配置模型时明确显示检索摘要模式；依据不足时拒答并提示缺少什么资料。

### J4：学习计划与课程

1. 用户从已授权知识库中选择资料、Wiki 页面或课程范围，并声明目标、时间、基础和偏好。
2. `plan-compose` Skill 结合所选内容、学习记录和来源生成计划候选。
3. 用户确认后计划生效并固定版本；调整计划创建新版本。
4. 课程按模块、学习单元和知识点组织资料，每个单元固定内容版本与完成规则。
5. 用户在原文阅读器中学习文字、PDF、图片或音视频；播放器保存页码、时间点和完成事件。
6. 学习事件追加记录，可重建进度，并为后续练习生成提供依据。

### J5：练习与测评

1. 用户可从当前学习单元、已学范围或薄弱知识点发起练习。
2. `practice-generate` 或 `assessment-generate` Skill 按知识点、难度和历史作答生成题目候选。
3. 正式题目必须绑定来源；`ai_completed` 内容不能自动进入正式题库。
4. 作答、响应时间、评分、反馈和题目版本追加写入数据库。
5. 客观题确定性评分；主观题按量表评分并记录置信度。
6. 低置信度或争议结果进入人工复核。
7. 评测结果更新掌握度快照和计划建议，不改写历史记录。
8. 系统从结构化学习记录生成可下载报告和报告图片；报告必须注明范围、时间和证据版本。

## 7. 非功能要求

### 7.1 安全

- 默认拒绝：空间数据、文件系统、网络和模型能力必须显式授权。
- 上传内容是不可信数据，不得改变 Agent 或 Skill 权限。
- 防止越权访问、路径穿越、恶意 MIME、压缩炸弹和资源耗尽。
- 密钥不得进入数据库明文、日志、前端包或 Wiki。
- 审计事件必须覆盖身份、权限、资源、Wiki、Skill、模型和正式测评变更。

### 7.2 一致性与可靠性

- 原始文件和 `ResourceVersion` 不可变。
- 数据库事务不能假定文件操作可回滚；跨存储操作使用明确补偿状态。
- Worker 任务必须幂等，崩溃后可重试或进入死信。
- 同一空间 Wiki 发布串行化；失败不影响已发布版本。
- 数据库、Blob 和 Wiki 的备份恢复点必须一致。

### 7.3 性能与规模基线

| 指标           | MVP 目标 | 部门级目标              |
| -------------- | -------- | ----------------------- |
| 单文件大小     | 100 MB   | 可配置至 2 GB，分片上传 |
| 单空间资料数   | 100      | 10,000                  |
| Wiki 页面数    | 数百     | 50,000                  |
| 普通 API P95   | < 500 ms | < 500 ms                |
| 查询首结果 P95 | < 5 s    | < 8 s                   |
| 任务进度延迟   | < 2 s    | < 2 s                   |
| 同时在线用户   | 10       | 200                     |

目标不构成当前已验证事实；达到相应里程碑时必须用压测报告确认。

### 7.4 可维护性

- 共享输入输出必须由 `packages/contracts` 定义并校验。
- 所有可变 Schema 都有 `schemaVersion` 和迁移策略。
- 每次输出可追溯到资源、Skill、模型和运行记录。
- 每个里程碑有自动化门禁和人工验收记录。

## 8. 数据与隐私策略

| 策略                            | 行为                                  |
| ------------------------------- | ------------------------------------- |
| `local_only`                    | 仅允许本地模型和本地工具处理正文      |
| `cloud_allowed`                 | 允许将所需片段发送给已批准云 Provider |
| `cloud_allowed_after_redaction` | 脱敏通过后才允许出域                  |

策略优先级高于质量、成本和 fallback。任何降级都不能突破空间策略。

## 9. 明确不在 v1 范围

- 多租户 SaaS、客户计费和公共市场。
- FastAPI 或独立 Python HTTP 服务。
- 向量数据库、Embedding 驱动的核心查询和图数据库。
- 移动 App、桌面同步 Agent 和离线多端编辑。
- 多 Agent 自主协作和无人审批的高风险动作。
- 自动公开发布知识内容。
- 视频生成产品界面。

## 10. 项目级成功标准

- 新环境可按文档安装、初始化、升级、备份和恢复。
- 授权用户能够完成资料上传、处理、Wiki 浏览、查询和精确回源。
- 100 份真实资料黄金集 Recall@10 ≥ 85%，引用准确率达到分类型目标。
- 所有正式题目、评分和学习状态都能回到当时的知识版本与来源。
- 系统在 Worker 崩溃、模型超时、Wiki Lint 失败和存储异常时保持可诊断、可恢复。
- 安全测试未发现跨空间读取、原始文件改写、未批准出网或提示注入提权。

## 11. 需求变更规则

- 新需求先分配功能域和里程碑，不直接进入代码。
- 改变数据模型、权限边界、运行时或知识真相源时必须新增 ADR。
- 改变用户旅程或验收标准时先更新本文件和对应分域 Spec。
- 未进入主实施计划、没有负责人/依赖/验收标准的需求不得开工。
