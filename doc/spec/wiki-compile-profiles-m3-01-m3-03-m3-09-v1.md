# Wiki 编译模式与内容分离 M3-01/M3-03/M3-09 Spec v1

## 1. 问题

- 当前上传只表达“处理这个文件”，没有表达希望把资料整理成知识、案例还是资料索引。
- 当前编译器把每个资源版本固定生成一个 `material` 页面，知识库列表因此混合了原材料索引和可复用知识。
- 资料库和知识库虽然已有独立路由，但知识库内部没有内容域选择，用户无法只管理需要的知识类型。

## 2. 目标

- 上传时明确选择 Wiki 编译模式：`knowledge`、`case`、`reference`。
- Parser 只负责忠实提取结构化节点，不根据用途改写源内容。
- Wiki Compiler 根据模式生成不同页面结构，并保存模式用于重试和追溯。
- 资料库管理原始文件、版本和任务；知识库管理发布后的语义页面。
- 知识库默认只显示知识内容，并提供独立“资料索引”视图。

## 3. 模式契约

| 模式        | 用户文案 | v1 输出                                        | 不做的推断                       |
| ----------- | -------- | ---------------------------------------------- | -------------------------------- |
| `knowledge` | 知识提炼 | `material` 总览 + 按标题或稳定窗口生成 `topic` | 不在无重复证据时自动生成 concept |
| `case`      | 案例整理 | 一个 `case` 页面，按源标题保留案例材料结构     | 不臆造背景、行动、结果或经验结论 |
| `reference` | 资料归档 | 一个忠实的 `material` 页面                     | 不进行语义拆分                   |

- 新上传默认 `knowledge`，避免用户继续得到只有一个结果的文档级知识库。
- 历史 `resource_version` 迁移默认 `reference`，保持既有产物语义不变。
- 自动判断、课程类、模型类在获得模型路由和审核机制后单独实施。

## 4. 数据与去重

- `ResourceVersion.compileProfile` 是不可变处理意图，任务重试必须复用它。
- 同一空间、同一文件哈希、同一编译模式视为重复上传。
- 同一文件选择不同模式可以创建新的处理版本，不跨模式误判为重复。
- 既有资料可使用显式 recompile API 从当前版本创建复用 Blob 的新模式版本；不能静默覆盖历史页面、旧版本或历史 SourceLocator。

## 5. 页面与管理边界

```text
/workspace/resources
└── 原始资料：文件、版本、处理状态、重试、编译模式

/workspace/wiki
├── 知识内容：topic / concept / case / course（默认）
└── 资料索引：material（可跳转资料库管理原文件）
```

- “知识内容”允许多选页面类型；至少保留一个类型。
- “资料索引”不等于原文件管理，只展示 Wiki 中的材料总览和来源。
- 搜索、状态过滤和页面阅读在当前内容域内生效。
- API 接受多个页面类型参数；旧单类型调用保持兼容。

## 6. 知识类拆分规则 v1

- 有一级或二级标题时，以这些标题作为稳定章节边界。
- 没有可用标题时，按最多 8 个节点或约 6000 字符的稳定窗口拆分。
- 页面 ID 使用 `resourceVersionId` 与首节点 ID 派生；重复编译必须稳定。
- 每个 topic 只携带自身节点的 `SourceLocator`，不能复制整份资料来源。
- `material` 总览只作为资料索引，不进入默认知识内容列表。

## 7. 影响面

- `packages/contracts`：编译模式、Wiki 多类型筛选和可选 Frontmatter 模式。
- `packages/database`：`resource_version.compile_profile` 与 SQL migration。
- `packages/core`：上传去重、版本写入和任务重试语义。
- `apps/worker`：把版本模式传给 Wiki Compiler。
- `packages/wiki`：模式路由、知识拆页和索引重建。
- `apps/web`：上传模式选择、资源模式展示、知识库内容域和类型多选。

## 8. 验收标准

- 上传表单可以选择三种模式，默认“知识提炼”。
- 数据库持久化模式；Worker 重试后仍使用相同模式。
- 同一文件同一模式返回重复；不同模式可分别处理。
- 知识模式对无标题长资料生成多个稳定 topic 页面，每页来源集合独立。
- 案例模式生成 `case` 页面，资料模式生成 `material` 页面。
- 知识库默认不显示 `material`；切换“资料索引”后只显示 `material`。
- 知识内容可多选 topic/concept/case/course，筛选结果正确。
- 原材料仍在资料库独立管理，知识库提供明确入口而不暴露服务器路径。
- 重复编译页面 ID、数量和来源集合稳定。
- `pnpm format:check`、`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 通过。

## 9. 非本轮范围

- LLM 自动判断编译模式。
- 自动概念归并、案例要素补全和课程编排。
- 历史任意版本的 recompile、版本回滚和自动选取模式。
- Wiki 审核、diff、人工锁和并发发布协议。
- 向量数据库或 Embedding 检索。
