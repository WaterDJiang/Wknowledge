# M7-10-B 组织任务队列隔离 Spec v1

## 1. 关联

- 工作包：`M7-10` 安全测试；关联既有 `M2-06` 任务重试与死信运维。
- 发现来源：2026-08-14 安全扫描的高风险“全局 pg-boss 死信队列暴露给组织管理员”。
- 影响面：管理员任务队列 API、设置页、`packages/core` 组织范围读取/重试，以及数据库回归。

## 2. 目标

- 组织管理员只能查看本组织资源版本的当前处理状态和当前失败项。
- 管理员只能为本组织当前失败资料创建新的、可追溯的处理任务。
- 租户 Web 控制面不读取或重驱全局 pg-boss 死信队列。

## 3. 领域规则

- 组织范围由 `processing_job → knowledge_space.organization_id` 确定；不从 pg-boss payload、队列名或客户端参数推断。
- 同一 `resourceVersion` 只显示最新处理任务作为当前状态；历史失败记录保留但不再作为可重试当前项。
- 重试使用既有 `retryProcessingJob` 创建新 `processing_job` 与 Outbox；原始文件、原处理记录和历史审计均不修改。
- 批次上限保持 100。并发造成的“已不再失败”或“已有活动重试”仅计为跳过，不跨组织重试。
- 现有全局 `readResourceQueueHealth` / `redriveResourceDeadLetters` 仅可保留作平台内部运维能力，租户 Web Route 不得调用。

## 4. 验收标准

- 两个组织均有失败任务时，组织 A 的状态和 JSON 不包含组织 B 的任务 ID、队列 payload 或可重试条目。
- 组织 A 重试只创建 A 的新任务/Outbox；组织 B 的失败任务保持不变。
- 重试后 A 的原失败记录仍在历史中，但最新状态为新的排队任务，不再显示为当前失败。
- 设置页明确表述为“当前组织的失败任务重新处理”，不再误导为全局死信重驱。
- 定向数据库回归、根格式、Lint、类型、单测、构建和 E2E 门禁通过。

## 5. 非范围

- 不删除 pg-boss 死信队列，不改变 Worker 的重试/死信配置。
- 不新增队列分片、Redis 或数据库迁移。
- 不提供跨组织平台运维 UI。
