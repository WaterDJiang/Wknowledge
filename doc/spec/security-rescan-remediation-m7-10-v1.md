# M7-10 复扫整改 Spec v1

## 1. 关联计划与状态

- 工作包：`M7-10-R1` 至 `M7-10-R6`。
- 依据：2026-08-14 标准安全复扫，报告产物位于本机安全工作台；本仓只记录可复现的整改范围与验收条件。
- 状态：开发中。发现未关闭前，不开启真实云模型对话、第三方/生成型 Skill 的生产可用性。

## 2. 目标

- 关闭撤权后 Agent 持续输出与环境变量 cloud Provider DNS 重绑定两个 high 问题。
- 收敛学习读取授权、来源预览内存、登录可用性和 PPTX 解析资源四个 medium 问题。
- 保持 Markdown-first、来源可追溯、原始文件不可变和 Worker 长任务边界。

## 3. 工作包与验收

| 工作包   | 问题                           | 实施范围                                                                                              | 验收标准                                                                       |
| -------- | ------------------------------ | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| M7-10-R1 | Agent SSE 撤权竞态             | Agent 每次证据读取、模型调用、SSE 发送与完成写入均重核全部 Binding 的空间/组织成员状态                | 运行中撤权后不再读取、发送或持久化回答；历史只保留脱敏审计                     |
| M7-10-R2 | 环境变量 Provider 旁路固定连接 | cloud 环境变量回退不注入全局 Fetch；生产 cloud 请求无条件使用已验证 DNS 地址的固定传输                | 工厂路径回归证明不会调用普通 Fetch；Host/SNI、allowlist 与取消语义保持         |
| M7-10-R3 | 学习计划/课程撤权读取          | 对 active plan、course、progress、练习、测评与报告按所有 ResourceVersion 重核当前空间及未禁用组织成员 | 禁用组织成员或移除任一空间成员后，读取与新写入均 fail closed                   |
| M7-10-R4 | 来源预览大范围内存             | 预览 API 限制单次范围、限流并改为流式读取；完整下载走独立受控入口                                     | 无 `Range`、开放 Range 与并发请求均不在 Web 进程分配整文件 Buffer              |
| M7-10-R5 | 登录对象级锁定                 | 在受控代理可信网络主体可用时采用账户与网络组合限流；否则采用不可被第三方耗尽的渐进延迟/挑战           | 五次伪造失败不锁定真实用户；伪造转发头仍不能绕过限流                           |
| M7-10-R6 | 文本/PPTX 解析预算遗漏         | 文本在 Blob 读取前检查版本大小；PPTX 在表格单元格遍历与拼接前施加单元格、字符与时间预算               | 超限文本不读取 Blob；高基数表格受控截断或拒绝，不导致 Worker 无界 CPU/内存增长 |

## 4. 影响面

- `apps/web`：Agent SSE、来源预览和登录限流。
- `packages/core`：学习资料授权、计划/练习/测评/报告读取与写入。
- `packages/agent-runtime`：可取消的授权重核边界。
- `packages/model-gateway`：环境变量 Provider 工厂和固定传输。
- `packages/blob-store`、`runtimes/python`：流式读取和 Office 解析预算。

## 5. 非范围

- 不改变现有 Markdown Wiki 查询路线，不引入向量数据库或 Embedding。
- 不将 Pi、OpenCode 或 Claude Code 直接赋予权限、文件系统、数据库或模型密钥控制权。
- 不以关闭本次 finding 为理由跳过 Docker、Sandbox 与真实 Provider 的后续运行时演练。

## 6. 门禁

- 每个整改先有失败回归，再做最小修复。
- 每个工作包至少运行定向测试；涉及 API 或 SSE 时补 Playwright 场景。
- 完成批次运行：`pnpm format:check`、`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm test:e2e`。
- R1、R2 完成后进行新的安全复扫；不得复用本次快照宣布问题已关闭。
