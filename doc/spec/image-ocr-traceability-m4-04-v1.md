# 图片 OCR 区域与精确回源 M4-04 Spec v1

## 1. 关联计划

- 工作包：`M4-04`，依赖 M2-02 受管上传准入、M2-08 `CompiledNode`、M4-08/M4-09 来源权限与预览。
- 状态：已验证。本切片只使用本地 Tesseract 提取 PNG/JPEG/WebP 的 OCR 文字行与像素区域；不调用云模型、视觉理解或图片生成。

## 2. 目标

- 用户可上传受支持图片资料，Worker 将 OCR 行写为带不可变 `ResourceVersion` 和 bbox 的 `image` SourceLocator。
- 从 Wiki、查询或学习内容打开引用时，来源页只显示同一图片、同一 OCR 区域和同一派生文字。
- 图片原件继续以受权只读方式提供；OCR 文字、原图与系统解释必须清晰区分。

## 3. 范围与安全约束

- 首批 MIME：`image/png`、`image/jpeg`、`image/webp`；扩展名、声明 MIME 和文件签名必须一致。
- Python 使用 Pillow 只读解码，拒绝超过 40,000,000 像素、异常尺寸和多帧图片；Tesseract 以固定参数、无 shell、30 秒超时运行。
- 每个 OCR 行的 bbox 为原图像素 `[left, top, right, bottom]`；空文字、无效 bbox 和超出原图边界的结果不生成节点。
- 单个行文本最多 8 KiB UTF-8，派生 TSV 总输出最多 4 MiB；超过上限或没有可用文字时任务失败，不生成“已理解图片”的伪内容。
- Worker 不访问业务数据库以外的 Python CLI 契约；OCR 过程不出网、不读取其他资源、不执行图片内文本中的指令。

## 4. 来源预览

- 新增只读 `image-preview` API：权限重核后只从同一资源版本的已发布 `nodes.json` 选择完全相同的 image bbox 节点。
- UI 在受权原图上以相对坐标显示 OCR 区域，并显示派生文字、像素范围和“仅为 OCR 文字”的提示。
- 不带 bbox 的历史图片定位沿用原件预览，不推断任何 OCR 内容；不存在 bbox 或跨版本不得回退到其他区域。

## 5. 验收标准

- PNG/JPEG/WebP 的有效签名被准入，伪造 MIME/签名被拒绝且不写 Blob/数据库/队列。
- 合成图片中的多行文字产生合法、边界内、不可变版本一致的 `image` SourceLocator；每行内容可在精确区域预览。
- 无文字、超像素、超时和超输出图片不产生虚构节点；OCR 只由 Worker 运行。
- Parser、范围选择、API/UI 权限入口及根质量门禁已通过；真实登录态图片上传、Worker 编译和区域预览点击流仍待可复用安全会话验收。
