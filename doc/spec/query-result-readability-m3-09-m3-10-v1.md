# 查询结果可读性 M3-09/M3-10 修复 Spec v1

## 1. 现场问题

- 回答正文直接截取 Wiki Markdown，导致 `> 来源：wk://...` 原始定位串显示给用户并产生横向溢出。
- 一个长 PDF 的全部 SourceLocator 都以相同“打开来源”链接平铺，64 个定位挤成不可读的一行。
- 中文查询被拆成单个汉字参与召回，仅命中“是”等常见字的弱相关资料也会进入回答。
- 回答正文、资料标题和引用链接缺少稳定换行与溢出保护。

## 2. 关联工作包

- `M3-09 Wiki UI`：回答与来源区域的信息层级、响应式布局和可访问性。
- `M3-10 Query`：查询词切分、候选最低相关度和回答摘要清洗。
- 本修复不替代已排期的 `M3-01/M3-03/M3-10` Wiki 页面粒度改造。

## 3. 目标

- 回答只显示可读正文，不出现内部 `wk://` URI。
- 中文查询不使用单个常见汉字召回页面；强相关页面保留，弱相关页面不混入回答。
- 每个引用先显示资料标题、定位数量和最多 3 个入口；剩余定位折叠后按需展开。
- 模型只引用部分证据时，页面仍显示本轮全部检索候选；“支持回答的证据”和“其他相关候选”必须有不同标签，不能把未引用候选误称为答案依据。
- 桌面和移动端均无横向溢出，长标题和错误摘要可以换行。

## 4. 范围

### 包含

- 查询词按拉丁词和连续中文 2–4 字片段提取，不使用单汉字。
- 候选页面应用相对最低分，过滤只命中通用短语的弱相关结果。
- 回答摘要移除 Markdown 标题符号、来源标记与原始 Locator，只选择相关正文块。
- 引用区改为卡片和折叠定位列表，链接带编号和明确可访问名称。
- 回答依据区之后展示可折叠的相关检索候选；候选数量使用 `EvidenceBundle.items`，不因模型选择较少引用而缩减为单条结果。
- 回答与引用容器增加 `overflow-wrap`、网格边界和移动端规则。

### 不包含

- 调用 LLM 重新生成自然语言答案。
- 改造 SourceLocator 预览器。
- 将长资料拆分成多个 Wiki 页面。

## 5. 验收标准

- 查询“DeepSeek是什么？”只返回包含 DeepSeek 证据的页面，不返回只包含“是”的页面。
- 回答文本不包含 `wk://`、`> 来源：` 或超长内部 URI。
- 64 个定位默认只展示前 3 个入口和“查看其余 61 个定位”。
- 展开后仍可访问全部定位；折叠状态下不形成链接文字墙。
- 当模型只引用 1 条、检索命中 3 条时，页面显示“1 条证据支持这个回答”及“另外检索到 2 条相关候选”；后者可展开并打开来源，但不标为回答证据。
- 1440px 和 390px 宽度均无横向溢出。
- 页面无框架错误覆盖层和新增控制台错误。
- `pnpm format:check`、`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 通过。
