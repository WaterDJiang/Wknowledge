# Wiki 页面粒度问题 M3-01/M3-03/M3-10 Spec v1

## 1. 阶段检查结论

- 当前 Wiki 列表 API 不限制结果数量，搜索会返回全部匹配的 Wiki 页面。
- 当前编译器固定按 `resourceVersionId` 生成一个 `material` 页面；长 PDF 的所有解析节点只成为该页面内的章节。
- 现场空间有 3 个资源页面；64 页 DeepSeek PDF 仍只对应 1 个 Wiki 页面和 64 个来源定位。
- 因此用户搜索某份长资料时通常只能看到一个文档级结果，无法从结果列表直接选择章节、主题或概念。

## 2. 目标

- 长资料能够稳定拆分为多个可独立检索的 Wiki 页面。
- 确定性页面粒度覆盖 `material` 总览和 `topic` 章节；可复用 `concept` 只有在重复证据、语义模型和审核机制具备后生成。
- 每个拆分页面只携带支持该页面正文的 `SourceLocator`，可直接定位到 PDF 页、文档节点或音视频分段。
- 根索引、分域索引、Wiki 浏览和 Query 使用同一批稳定页面 ID。

## 3. 关联工作包与排期

- `M2-08`：先稳定 CompiledNode 层级、顺序和父子关系。
- `M3-01`：扩展页面 Schema 与稳定 ID 规则。
- `M3-03`：实现材料总览、章节和概念页面的幂等编译。
- `M3-10`：按页面与 compiled 节点返回多个候选结果。
- `M3-12`：在页面粒度完成后执行黄金集 Recall@10 验收。
- 顺序：`M2-08` 契约已验证，本工作包是下一实施单元，必须在 `M3-12` 前完成。

## 4. 验收标准

- 64 页、多章节 PDF 不再只生成一个可搜索页面。
- 重复编译保持页面 ID、页面数量和来源集合稳定。
- 搜索章节词能够返回对应章节页面，而不是整份资料全文。
- 搜索跨资料主题能够返回多个候选页面，并按相关度排序；跨资料 concept 归并留在语义层工作包。
- 每个搜索结果至少有一个可解析来源；不得把整份资料的全部来源复制到每个子页面。
- 人工审核页面不被重新拆分静默覆盖。
- 不引入向量数据库或隐式 Embedding 调用。

## 5. 本轮不实施

- 本文件只记录问题、设计边界和排期；不在实时处理 UI 切片中顺手改写编译器。
- 具体拆分阈值、标题层级和概念抽取策略在 M2-08 契约稳定后冻结。

## 6. 2026-08-12 实施调整

- 已实现 `knowledge` 模式：一级/二级标题是首要拆页边界；每个标题章节内部仍按最多 8 个节点或约 6000 字符继续拆页，无标题资料使用相同阈值。
- 标题章节的续页以首个标题节点保持稳定 ID（例如 `topic-{version}-chapter-part-02`），沿用章节标题上下文，但不复制标题节点或其来源定位。
- 已验证 Markdown 真实上传生成 3 个稳定 topic，页面来源集合不复制整份资料。
- 新增回归验证：一个一级标题下的 17 个正文节点从 1 个页面拆为 3 个稳定 topic，查询“学习方法”返回全部 3 页，每页来源不超过 8 个节点。
- 根据知识质量约束，v1 不从单份资料确定性伪造 concept；concept 归并等待模型路由、重复证据和审核锁。
