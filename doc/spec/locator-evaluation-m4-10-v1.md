# 多模态来源定位评测 M4-10 Spec v1

## 1. 关联计划

- 工作包：`M4-10`，依赖 M4-01 至 M4-06 的解析节点和 M4-08/M4-09 的历史版本来源预览。
- 状态：部分验证。本切片已建立可重复的解析定位基线与机器门禁；它不替代真实资料盲测或人工 95% 定位验收。

## 2. 目标

- 用同一评测器判断预期 `SourceLocator` 与解析实际定位是否一致。
- 先覆盖已具备解析夹具的 PDF、PPTX、CSV/XLSX 与图片 OCR；音频/视频沿用同一报告格式，在 ASR/字幕夹具稳定后接入。
- 报告必须按类型给出样本数、命中数、准确率和失败原因，不能以一条总分掩盖某一类型退化。

## 3. 判定规则

- 所有类型先严格比较不可变 `resourceVersionId` 与 `type`。
- PDF 比较页码；若提供 bbox，要求坐标有限、正面积、位于预期容差区域内，并报告 bbox IoU。
- 图片比较 bbox 的边界、预期文本所在区域与 IoU；默认阈值为 0.8，当前合成文字行夹具明确使用 0.75 容差以容纳本地 OCR 的字形边界差异；不把无 bbox 的整图引用算作 OCR 区域命中。
- 表格严格比较 `sheet + range`；幻灯片严格比较 `slide + shapeId`，仅 slide 级备注不替代指定 Shape。
- 音频/视频比较起止时间；允许的毫秒误差必须显式写在样例中，默认不允许误差。
- `document` 节点严格比较 `nodeId`。类型不匹配、资源版本漂移、缺失实际定位、无效 bbox 或超出容差一律失败。

## 4. 数据与边界

- 初始数据只使用临时目录中的合成资料和已有 Python JSON CLI；不读取用户资料、生产数据库或真实知识正文。
- 夹具的预期页码、范围、Shape、区域和时间段必须由人工写入测试，不得从同一解析输出反向生成预期值。
- `pnpm eval:locators` 输出 JSON 报告并在任何失败或未达配置阈值时返回非零；报告只写调用方指定路径，默认不写项目目录。
- 评测器不调用模型、Embedding、网络或数据库，也不修改 `raw/`、已发布 Wiki 或历史来源。

## 5. 验收标准

- PDF、PPTX、CSV/XLSX、图片 OCR、音频 ASR 与视频音轨转写各至少有一条人工预期的合成夹具，且通过同一个评测器报告。
- 报告按文件类型列出 `evaluatedCount`、`matchedCount`、`accuracy` 和具体失败原因；运行两次结果一致。
- 资源版本错误、页码/范围/Shape 错误、bbox 无效或越界、媒体时间偏移超阈值均有失败回归。
- `pnpm eval:locators`、定向测试、格式、Lint 与类型检查通过。

## 6. 后续门禁

- 真实资料定位盲测必须在授权、去敏、人工标注后执行，并单独记录 PDF 抽样定位准确率不低于 95%。
- 音视频需在 ASR/字幕真实样例上确认“不超过一个转写分段”的误差，才能开放其学习播放定位验收。
- 浏览器登录态的“引用 → 历史原件 → 位置高亮”人工验收不由本机器基线替代。
