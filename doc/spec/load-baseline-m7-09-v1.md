# M7-09 可复现负载基线 Spec v1

## 1. 关联计划

- 工作包：`M7-09 性能压测`，依据项目章程 7.3 的普通 API P95 小于 500ms、查询首结果 P95 与进度延迟目标。
- 当前切片：提供无外部依赖的 Web/数据库 readiness 负载工具和机器可读报告；它不是部门级 200 人验收。

## 2. 目标

- 在本地或显式授权的 staging 环境，以固定请求数、并发和只读端点测量吞吐、成功率、P50/P95/P99、最慢响应。
- 默认只访问 localhost 的 `/api/health`、`/api/health/ready`，不创建用户、上传资料、触发 Worker、调用模型或读取知识正文。
- 生成与原始负载参数绑定的 JSON 报告，报告不包含 Cookie、Authorization、环境变量、URL query、响应正文或堆栈。

## 3. 规则

- `pnpm test:load` 只允许 `http://127.0.0.1` 或 `http://localhost`；远程目标必须同时使用显式命令参数和 `WKNOWLEDGE_LOAD_ALLOW_REMOTE=true`。
- 默认 100 请求、10 并发；参数范围为请求 1–100,000、并发 1–500、超时 100–60,000ms。响应状态 200–399 为成功。
- `/api/health` 是控制面基础存活基线；`/api/health/ready` 覆盖数据库轻量查询。它们通过不能证明查询/上传/Worker/模型达到目标。
- 每次报告必须写明端点、请求数、并发、超时、时间戳、延迟分位数、成功/失败数和每秒完成数；不得从健康检查结果推断 200 同时在线用户容量。
- 正式部门级验收必须在隔离 staging、固定硬件/容器配额、独立测试库、合成 10,000 资料/50,000 页面数据和授权账号下增加 API、查询、SSE、上传与 Worker 混合场景；报告须与本基线分开保存。

## 4. 验收

- 参数、远程目标和非 localhost 默认值均被拒绝；未授权远程 URL 不产生请求。
- 合成 `fetch` 回归覆盖并发、P95 计算、失败计数、请求超时和无响应正文输出。
- 本地服务运行时可产出 schema 稳定 JSON；报告中不存在 Cookie、Authorization、数据库 URL、响应正文或凭据。
- 根质量门禁通过；部门级目标保持“未验收”，不因该脚本存在而变更状态。

## 5. 非范围

- 生产压测、带真实资料/真实模型的负载、自动扩缩容建议、分布式压测、k6 云服务、压测结果自动写入数据库或用户可见监控页面。
