# 视频音轨转写 M4-06 Spec v1

## 1. 关联计划

- 工作包：`M4-06`；依赖 M4-05 的受管 ASR、M4-07 媒体探测、MP4 准入和不可变 ResourceVersion。
- 状态：开发中。

## 2. 目标

- 对含音轨且存在符合空间数据策略的受管 ASR Provider 的 MP4，在 Worker 本地提取第一条音轨并生成带视频时间定位的转写节点。
- 视频容器、内嵌字幕和音轨转写是三种不同证据；不得由音轨文本推断画面内容。

## 3. 范围与规则

- Worker 先以 `ffprobe` 解析流清单；只选择第一条已声明的音频流，由 `ffmpeg` 从受管只读 LocalBlob 在受控临时目录转为单声道 16 kHz WAV。原始 Blob 不复制、不改写，临时派生产物在调用完成或失败后删除。
- 仅当视频确有音频流且 Provider 在运行时仍健康、启用、能力匹配且空间策略相容时调用 ASR；没有音轨或 Provider 不可用时照常发布视频元数据和已有字幕，不创建失败任务。
- 音轨转写重用 M4-05 的 `verbose_json` 分段校验。每一段使用同一 ResourceVersion 的 `video startMs/endMs`；无效或缺失分段退回完整视频时段。
- 每次执行至多处理 512 MiB 原始 MP4、2 小时媒体时长和 256 MiB 临时 WAV；超限时明确跳过音轨转写并保留其他已验证视频证据。
- 审计只保存 Provider、模型、耗时和“已完成/跳过”的原因代码，不保存媒体字节或转写正文。

## 4. 验收

- 含音轨的受管 LocalBlob MP4 经实际 `ffmpeg` 生成音轨转写，Provider 分段可跳转到视频时间点。
- 无音轨、无 Provider、超限和提取失败均不妨碍 MP4 以容器/字幕证据完成入库。
- 临时目录不会残留原始视频或音频产物；取消、策略和全仓回归不退化。

## 5. 不包含

- 多音轨选择 UI、外挂字幕、说话人分离、词级时间戳、关键帧、OCR、画面描述和 `video_understanding`。
