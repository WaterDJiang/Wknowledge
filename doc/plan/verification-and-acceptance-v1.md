# 验证与里程碑验收策略 v1

## 1. 目标

将“实现完成”转换为可复现证据。每个工作包记录命令、数据集、结果和产物；里程碑只有全部退出门禁通过才标记已验收。

## 2. 测试层级

| 层级   | 目标                                 | 主要工具                     |
| ------ | ------------------------------------ | ---------------------------- |
| 静态   | 格式、规则、类型、依赖边界           | Prettier、ESLint、TypeScript |
| 单元   | 领域规则、合并、权限、路由、评分     | Vitest                       |
| 契约   | HTTP、Skill、Python CLI、Schema      | Vitest、JSON fixtures        |
| 集成   | PostgreSQL、pg-boss、Blob、Wiki 发布 | Vitest + Docker              |
| E2E    | 浏览器关键用户旅程                   | Playwright                   |
| 黄金集 | 检索、引用、解析质量                 | evaluation scripts           |
| 安全   | 越权、输入、提示注入、沙箱           | 专项测试                     |
| 故障   | 崩溃、超时、磁盘、并发、恢复         | fault fixtures/scripts       |
| 性能   | API、队列、查询和并发容量            | k6 或等价工具                |

## 3. 环境

- `unit`：无数据库、无网络，快速且确定。
- `integration`：临时 PostgreSQL 和临时文件根，测试后清理。
- `e2e`：独立数据库、固定种子、Web+Worker，不复用开发数据。
- `golden`：受控真实资料集，版本化预期答案和来源。
- `staging`：接近生产拓扑，用于恢复、安全和压测。

禁止让自动化测试依赖个人开发库、浏览器现有 Cookie 或手工生成的临时文件。

| 里程碑 | 必需证据                                                        |
| ------ | --------------------------------------------------------------- |
| M0     | 根命令、Harness 13 项、CI 运行、文档导航                        |

| M2     | 上传/版本 E2E、Worker 崩溃恢复、死信、实时进度                  |

## 5. 固定质量命令

```bash
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

完整用户流程：

```bash
pnpm test:e2e
pnpm eval:wiki
```

后续新增并固定：

```bash
pnpm test:integration
pnpm test:security
pnpm test:fault
pnpm eval:locators
pnpm test:load
```

这些命令在脚本实际存在前不能写入 Harness 的“实际命令”区。

## 6. 验收记录格式

每个里程碑创建 `doc/log/{date}.md` 中的独立章节：

```text
目标与版本
范围和工作包 ID
环境与数据集版本
执行命令及退出码
自动化结果
人工旅程结果
性能/安全/黄金集指标
已知限制
验收结论：通过 / 有条件通过 / 不通过
验收人和日期
```

“有条件通过”不能把状态改成已验收，必须列出关闭条件。

## 7. 黄金集治理

- 资料、问题、预期页面、预期 SourceLocator 和拒答样例均版本化。
- 训练/调试样例与最终盲测样例分离。
- 指标按文件类型、语言、问题类型和资料规模分层报告。
- 模型或 Skill 变更必须与上一个稳定版本对比，不能只报单次结果。
- 人工纠正黄金集需要审核记录，防止为了让测试通过而降低标准。

## 7.1 Agent 与学习闭环评估

- Agent Adapter 使用脚本化 Provider 验证消息、工具、停止、错误和事件顺序，最少 20 条确定性轨迹。
- 会话权限测试覆盖双空间绑定、跨空间拒绝、撤权后拒绝、绝对路径和路径穿越。
- 多轮上下文测试至少 20 轮，压缩前后保留系统策略、最近问题、未完成工具状态和引用证据。
- 学习 E2E 覆盖选择内容、计划候选/确认、原文进度恢复、练习提交、评分入库和报告生成。
- 报告契约测试逐项比较 LearningReport JSON、Web 页面、PNG/PDF 使用的核心指标输入。
- 音视频学习流程只有在 M4 时间定位评测通过后进入 M6 验收。

## 8. 缺陷门槛

- P0/P1 缺陷为 0 才能里程碑验收。
- P2 必须有明确负责人、规避方式和关闭版本。
- 权限、原件损坏、历史证据漂移、未批准出域和恢复失败一律阻止发布。
- 测试不稳定必须记录并修复，不允许通过静默重试掩盖。
