# M7-10 复扫整改排期 v1

## 1. 前置结论

2026-08-14 的标准复扫在当前快照中确认 2 个 high、4 个 medium。它不否定已有的 M7-10 基础修复，但说明原有状态不能再写为“high 清零”。

## 2. 执行顺序

```text
R1 运行中 Agent 撤权
  └─→ R2 cloud Provider 固定传输工厂
       └─→ 真实 Provider/对话产品验收

R3 学习来源授权
  └─→ 生成型学习计划、练习、测评入口

R4 来源预览资源边界 + R6 PPTX 解析预算
  └─→ 多媒体/Office 生产规模验收

R5 登录限流可用性
  └─→ 反向代理部署验收
```

## 4. 与 M5/M6 产品化的关系

- M5 对话保持“Binding → `knowledge.search/read` → EvidenceBundle → 自然语言答复 + 来源区”；R1 是该链路的运行中授权门。
- M5 的 Pi/OpenCode/Claude Code 采用仍为 Adapter/模式参考；R2 未关闭前不开放 cloud Provider 的生产模型调用。
- M6 保持“选材 → 候选 → 用户确认 → 固定原文 → 练习/测评 → 入库评分 → 报告图片”；R3 未关闭前不得开启生成型计划或题目入口。
- R4/R6 只加资源安全边界，不改变 SourceLocator 或固定版本原文契约。
